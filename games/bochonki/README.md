# Бочонки

HTML5-игра для Яндекс Игр: классическое русское лото как узнаваемый вход, за
которым открывается «Карточка мастера» — roll-and-write на поле 5×5, где бочонки
расставляет сам игрок и вернуть ход нельзя.

Концепт и обоснование выбора — в [`docs/YANDEX_GAMES_MARKET.md`](../../docs/YANDEX_GAMES_MARKET.md), раздел 7.

## Что уже сделано

- **Два режима.** Лото с двумя соперниками и ведущим; «Карточка мастера» с тремя
  системами очков, открывающимися лесенкой (строки → столбцы → диагонали).
- **Обучение подсветкой.** Каждая свободная клетка всегда показывает, сколько даст
  постановка. Подсказка и финальный счёт считаются одним и тем же кодом, и это
  закреплено тестом: сумма всех подсказок обязана равняться итоговому счёту.
- **Партия дня.** Мешок детерминирован датой по серверному времени — у всех игроков
  в сутки одна и та же последовательность, поэтому лидерборд измеряет решения, а не удачу.
- **Коллекция.** 40 достижений, битовая маска в base64.
- **Заменитель лидерборда для неавторизованных:** медиана, распределение результатов
  и личный рекорд по последним 30 партиям.
- **Локализация RU / EN / TR,** полнота проверяется тестом.
- **Ноль ассетов.** Вся графика — CSS, звук синтезируется через WebAudio.
  Архив 31 КБ при лимите платформы в 100 МБ.

## Разработка

```sh
npm test                 # 32 теста: очки, мешок, карточка лото, локализация, достижения
python3 -m http.server 8777   # затем открыть http://127.0.0.1:8777/
./build.sh               # собрать build/bochonki.zip для консоли разработчика
python3 tools/bundle.py  # собрать build/bochonki-single.html — вся игра одним файлом
```

Сборки нет намеренно: нативные ES-модули, никакого шага транспиляции.
Игра запускается и без SDK платформы — тогда платформенные функции молча отключаются.

## Структура

```

src/master.js      режим «Карточка мастера»
src/lotto.js       режим классического лото
src/lottoCard.js   генератор карточки 3×9 с валидатором

src/stats.js       локальная статистика
src/i18n.js        RU / EN / TR

store/             иконка каталога
tools/bundle.py    сборка всех модулей в один файл (для превью и шаринга)
```

## Загрузка в консоль

Порядок по [официальной документации](https://yandex.ru/dev/games/doc/ru/console/add-new-game):

1. Зарегистрировать аккаунт разработчика в [консоли](https://games.yandex.ru/console).
2. **Добавить игру** → заполнить вкладку **Черновик**.
3. Вкладка **Настройки** → проверить разрешённые хосты. У «Бочонков» внешних
   запросов нет вообще, кроме самого SDK, — список можно оставить пустым.
4. Вкладка **Страны и регионы** → выбрать страны дистрибуции.
5. **Отправить на модерацию**.

Черновик можно сохранить без отправки: статус станет «Создан», поля и архив
можно править дальше.

Обязательные поля черновика: Название, Об игре, Как играть, Версия, Категории,
Иконка, Обложка, Архив, Поддерживаемые платформы, Ориентация.
Для «Бочонков»: платформы — десктоп и мобильные, ориентация — обе.

### Промоматериалы

**Точные размеры в пикселях платформа в документации не публикует** — она прямо
пишет, что актуальные стандарты формата и объёма указаны в самой форме заполнения
черновика, потому что меняются. Проверять надо в форме, а не по чужим статьям.

Что подтверждено [требованиями](https://yandex.ru/dev/games/doc/ru/concepts/requirements):

- Это **два разных изображения**: иконка (строго квадратная) и обложка (широкая).
  Не два формата одной иконки — у них разные роли в каталоге.
- Иконка **без скруглений и без рамок**.
- Скриншоты нельзя использовать как иконку или обложку.
- Промоматериалы не должны содержать элементы системного интерфейса
  (статус-бар, индикатор батареи) и интерфейса самих Яндекс Игр.
- Скриншоты должны быть локализованы под каждый заявленный язык.
- Название игры на промоматериалах должно совпадать с названием в консоли.

Заготовки в `store/` сделаны с запасом по разрешению, чтобы уменьшить их
до любого размера, который потребует форма:

| Файл | Назначение |
|---|---|
| `icon-1024.png`, `icon-512.png` | квадратная иконка, без скруглений и рамок |
| `cover-1600x940.png` | широкая обложка, ключевые элементы с отступом от краёв под кроп |
| `shot-{ru,en,tr}-1-menu.png` | скриншот меню на трёх языках |
| `shot-{ru,en,tr}-2-master.png` | скриншот «Карточки мастера» |
| `shot-{ru,en,tr}-3-lotto.png` | скриншот режима лото |

Пересобрать промоматериалы: `store/icon.html` и `store/cover.html` — обычные
HTML-страницы, скриншот с них снимается любым браузером.

## Лидерборды

Игра отправляет результаты в две таблицы, их нужно создать в консоли **до** релиза,
иначе вызовы просто ничего не сделают.

| Техническое название | Что попадает | Сортировка |
|---|---|---|
| `daily` | результат партии дня | по убыванию |
| `best` | личный рекорд | по убыванию |

При создании заполняются: техническое название (именно оно используется в коде),
локализованные названия для каждого языка, тип результата — `numeric`,
направление сортировки — по убыванию, и флаг основного лидерборда
(его логично поставить на `daily`).

Ограничения платформы на вызовы: запись результата — 1 запрос в секунду,
чтение позиции игрока — 60 запросов за 5 минут, чтение таблицы — 20 за 5 минут.
Игра пишет результат один раз в конце партии, так что в лимиты укладывается с запасом.

Важно: запись результата работает только для авторизованных игроков. Для остальных
в игре показывается локальная статистика — это сделано намеренно, потому что
значимая доля аудитории платформы играет без входа в аккаунт.

## Сознательно отложено в патчи

Отложено, чтобы не растить срок первого релиза, — обосновано в концепте:

- ТВ-раскладка под пульт (ниша почти пустая, но IAP на ТВ запрещены)
- Режим «на двоих за одним столом» (категория локального коопа пуста)
- Открываемые карточки с новыми наборами правил — основная мета после релиза
- IAP: отключение рекламы, наборы карточек, оформление стола
- A/B-тест иконки: гонять 7–14 дней и смотреть на плато, а не на первые дни
