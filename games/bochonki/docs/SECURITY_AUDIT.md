# Аудит безопасности «Бочонков»

Проведён по методике скилла `security-audit` из Claude Code Game Studios,
адаптированной под клиентскую HTML5-игру без серверной части.
Дата: 17.08.2026. Каждая находка проверена воспроизведением, а не рассуждением.

## Сводка

| ID | Severity | Находка | Статус |
|---|---|---|---|
| SEC-001 | HIGH | Подменённое сохранение попадало в таблицу лидеров | **исправлено** |
| SEC-002 | MEDIUM | Счёт вычисляется на клиенте, серверной проверки нет | принятый риск |
| SEC-003 | MEDIUM | Без серверного времени «день» задают часы устройства | **исправлено** |
| SEC-004 | LOW | Слияние сохранений доверяет большему `gamesPlayed` | принятый риск |
| SEC-005 | INFO | XSS сейчас нет, но появится при выводе имён игроков | предупреждение на будущее |

---

## SEC-001 (HIGH) — подмена сохранения доходила до лидерборда. Исправлено

**Было.** В таблицу `best` отправлялось `save.best` — поле из сохранения, которое
лежит в `localStorage` открытым JSON и правится через devtools за пять секунд.

**Воспроизведение.** Записали в сохранение `best: 999999`, сыграли честную партию
на 50 очков. В лидерборд ушло `best=999999`.

**Стало.** Отправляется `s.total` — счёт только что сыгранной партии, и только
когда рекорд действительно побит. Повтор атаки: партия на 84 очка при подменённом
`best: 999999` не отправила ничего. Честный игрок при этом свой результат отправляет.

Подмена сохранения по-прежнему возможна, но теперь она портит только собственную
статистику игрока и не попадает в общую таблицу.

## SEC-002 (MEDIUM) — счёт считается на клиенте. Принятый риск

Игра целиком клиентская, серверной части нет. Любой может вызвать
`ysdk.leaderboards.setScore('daily', 999999)` из консоли браузера. Устранить это
без бэкенда невозможно — свойство всех клиентских игр на платформе.

Смягчающее обстоятельство: мешок партии дня детерминирован сидом, поэтому
результат в принципе проверяем — но проверять его некому. Заводить бэкенд ради
защиты таблицы лидеров в игре такого масштаба нерентабельно.

Что делать, если станет проблемой: перевести партию дня на лидерборд, где
показываются только друзья, либо принимать результат вместе с журналом ходов
и проверять его на сервере.

## SEC-003 (MEDIUM) — часы устройства решали, какой сегодня день. Исправлено

**Было.** `now()` = локальное время плюс поправка от сервера. Если `serverTime()`
не ответил, поправка оставалась нулевой и день определялся часами устройства:
переведя их, можно переигрывать удачный мешок дня.

**Стало.** Добавлен флаг `timeVerified`. Пока серверное время не подтверждено,
партия дня играется, но её результат в общую таблицу не отправляется.

## SEC-004 (LOW) — слияние сохранений. Принятый риск

При расхождении локального и облачного профиля выигрывает тот, где больше
`gamesPlayed`. Подменив локальное значение, можно затереть облачный профиль.
Вредит только самому игроку, общие таблицы не затрагивает.

## SEC-005 (INFO) — вывод чужих строк. Предупреждение на будущее

Сейчас XSS-вектора нет: интерфейс собирается через `innerHTML`, но все подставляемые
строки либо наши собственные из словарей локализации, либо числа, и экранирование
`esc()` применяется последовательно.

**Риск появится, когда мы начнём показывать таблицу лидеров с именами игроков** —
это строки, которые пишут посторонние люди. Их обязательно пропускать через `esc()`.
Отмечено здесь, чтобы не забыть при реализации.

## Чего не найдено

- Секретов, ключей и токенов в клиенте нет
- Внешних запросов нет вообще, кроме самого SDK платформы
- Повреждённая база достижений не роняет игру — декодирование обёрнуто в try/catch
  и проверено тестом
- Размер сохранения ограничен и не даёт превысить лимит платформы
