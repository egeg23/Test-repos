# Правила разработки игр под Яндекс Игры

Действуют для всего, что лежит в `games/`. Написаны по итогам «Бочонок» —
каждый пункт закрывает грабли, на которые мы уже наступили.

## Инструменты

Скиллы из [Claude Code Game Studios](https://github.com/donchitos/claude-code-game-studios),
адаптированные под нас, лежат в `games/.claude/skills/`. Что взято и что
сознательно отброшено — в `games/.claude/ADOPTION.md`.

Применять по ситуации, а не ритуально:

| Когда | Скилл |
|---|---|
| Перед подачей любой игры | `security-audit`, `launch-checklist` |
| Правки баланса или новая механика | `balance-check`, `quick-design` |
| Есть живые игроки | `playtest-report` |
| Жалобы на тормоза, слабый Android | `perf-profile`, `soak-test` |
| Объём растёт до релиза | `scope-check` |
| Новый язык или строки | `localize` |

Производственный конвейер фреймворка (GDD → эпики → истории), спринты,
командные оркестраторы и специалистов по движкам **не применять**: у нас соло,
ванильный JS без движка и цикл в 4–8 недель. Хуки фреймворка не установлены.

## Чек-лист консоли — соблюдать строго

23 пункта формы черновика. Проверять **кодом и запуском**, а не по памяти.
Каждое исправление закрывать регрессионным тестом, иначе вернётся.

### SDK и инициализация
- **§1.1** SDK только с `https://yandex.ru/games/sdk/v2`, инициализация без ошибок.
- **§1.19** Game Ready API. Формулировка «сразу после первой отрисовки» —
  недостаточна, на ней нас уже отклонили. Точное правило:
  - `LoadingAPI.ready()` вызывать **в кадре, в котором меню появилось на экране**:
    `go('menu')`, затем `requestAnimationFrame(() => sdk.loadingReady())`.
    Раньше нельзя (ещё видна загрузка), позже нельзя (игра уже играбельна).
  - **В критическом пути до показа меню не должно быть ни одного сетевого вызова.**
    `serverTime()`, `getPlayer()`, `getLeaderboards()`, чтение облачного
    сохранения — всё это выносить в отложенную фазу после показа меню.
    Локальное сохранение читать синхронно из localStorage.
  - Проверять замером под искусственной задержкой сети: при +3000 мс на каждый
    вызов SDK меню и `ready()` обязаны появляться за те же ~100 мс.
  - `GameplayAPI.start/stop` по границам партии **и вокруг каждого показа рекламы**.
- **§2.14** Язык из `ysdk.environment.i18n.lang` при запуске, до первой отрисовки.
  Кэш языка **не должен перебивать платформу** — модерация переключает языки
  через debug-панель. Неподдерживаемый язык откатывать на резервный.
- **§1.14** Запуск в режиме черновика до отправки — делает человек.

### Техническое качество
- **§1.14** Никаких зависаний. У любого показа рекламы обязателен сторож на
  случай, когда SDK не присылает ни `onClose`, ни `onError`. Сторож снимать
  по `onOpen`, иначе он оборвёт идущий ролик.
- **§1.14** Ноль JS-ошибок в консоли. Проверять на **собранном архиве**, а не на исходниках.
- **§1.15** Без фризов. Замер на реальном бюджетном Android — за человеком.
- **§1.9** Прогресс между сессиями через `getPlayer().setData` плюс localStorage.
  Финальное сохранение с `flush: true`, промежуточные не чаще раза в 5 секунд
  (лимит 100 запросов / 5 мин), объём до 200 КБ.
- **§1.10** Проверять вёрстку на 320, 360, 412, 768 и 1280 px. Горизонтальной
  прокрутки быть не должно ни на одной ширине.

### Интерфейс
- **§1.6** Подавлять `contextmenu` на игровом контейнере — правый клик и долгий тап.
- **§1.3** Звук глушить при потере фокуса страницы. Таймеры геймплея на скрытой
  вкладке останавливать: игрок не должен вернуться к проигранной партии.

### Реклама
- Вызов строго `showFullscreenAdv({ callbacks: {...} })` — объект с полем
  `callbacks`, а не колбэки напрямую. В сигнатуре документации параметр назван
  `callbacks`, и по ней легко ошибиться.
- **§4.7** Звук глушить на время ролика через `onOpen`, возвращать при закрытии.
- **§4.4** Полноэкранная только там, где геймплей объективно остановлен, и не
  после каждой партии. Внутри партии рекламы нет.
- **§4.5** На кнопке rewarded **прямо написать, что последует ролик**. Награда
  выдаётся только в `onRewarded`. Если реклама недоступна — выдавать бонус
  бесплатно, игра не должна ломаться из-за незагрузившегося ролика.
- Защита от повторного завершения: `onClose` и `onError` могут прийти оба.
- Sticky-баннер показывать вне партии и прятать на время игры.

### Языки
- **Последующие игры делаем на двух языках: русский и английский.** Турецкий
  больше не заявляем: он даёт трафик, но утраивает объём промоматериалов
  (обложка, пять скриншотов и полный перевод на каждый заявленный язык),
  а без полного комплекта черновик не уходит на модерацию.
- «Бочонки» остаются на RU/EN/TR — игра уже подана, трогать её не нужно.

### Материалы черновика
- **§2.7** Возрастной рейтинг — ставит человек.
- **§5.12** Проверять уникальность названия по каталогу до подачи.
- **§2.3** Описание обязано соответствовать тому, что реально в игре.
- **§2.10** Локализация полная. Заявили язык — переведено всё, включая
  названия достижений и аварийные экраны.
- **Полный комплект медиа на КАЖДЫЙ заявленный язык** — иначе черновик не уйдёт
  на модерацию с ошибкой «не хватает медиа файлов для одного из языков».
  Обложку с текстом делать локализуемой и рендерить по одной на язык.
- Название на промоматериалах обязано **совпадать** с названием в консоли
  для этого же языка. Если в консоли названия локализованы — на обложке
  для en должно стоять английское название, а не русское.
- Обложка 800×470 PNG. Иконка строго квадратная, без скруглений и рамок.
  Скриншоты локализовать под каждый заявленный язык.

### Контент
- **§3.4** Нет запрещённого контента. **Если тема игры граничит с азартной**
  (лото, карты, рулетка, кости) — выносить отдельный раздел в комментарий
  модератору: нет ставок, денежных призов, обмена на деньги и внутриигровой валюты.
- **§3.5** Растровых ассетов со стороны не брать. Рисовать кодом, звук синтезировать.
- **§3.6** Оригинальная разработка, не клон.
- Про использование ИИ отвечать честно.

## Комментарий для модератора

**Лимит поля 2048 символов** — закрывать тестом, иначе превышение обнаружится
в момент подачи. Обязательно закрывать два вопроса:
объём контента (**§2.9**) и, если тема требует, азартную составляющую (**§3.4**).
Партия в 3–5 минут без пояснения объёма — типовой отказ.

## Наши инварианты

- **Ноль растровых ассетов.** Графика кодом, звук через WebAudio. Билд в десятках килобайт.
- **Без движка и без шага сборки.** Ванильный JS с ES-модулями. Godot Web (~40 МБ)
  и Unity WebGL (~13 МБ) несовместимы с нашим весом.
- **Подсказка не может расходиться с механикой.** Если интерфейс что-то обещает
  игроку — это считается тем же кодом, что и результат, и закрывается тестом.
- **В лидерборд уходит только значение из реальной партии.** Никогда из сохранения:
  localStorage правится через devtools.
- **Проверять на собранном архиве.** Работоспособность исходников ничего не доказывает.
- **Аудитория платформы:** 45+ около половины, женщин 58%, десктоп 40%.
  Без рефлексов и таймеров, зоны нажатия от 56 px, цифры от 28 px, высокий контраст.

## Порядок перед подачей

1. `npm test` — зелёные.
2. `./build.sh`, распаковать архив, прогнать по всем экранам, проверить консоль.
3. Прогнать `security-audit` и разобрать чек-лист выше по пунктам.
4. Обновить тексты консоли и комментарий модератора, проверить лимит.
5. Собрать комплект для человека с инструкцией по шагам.
